01The idea

Every step in a skill belongs to someone.

A skill is a list of steps. You, the model, or code can take each one. Most skills never say which, so the model ends up taking all of them, including the ones it is bad at.

You

Read, decide, approve

It costs your time, so spend it on the calls only you can make.

The model · probabilistic

Choose, summarise, write

It can answer differently on the next run, or on another model. That is fine for judgement and bad for arithmetic.

Code · deterministic

Count, sort, compare, convert

The same input gives the same output on every run and every model. It costs almost nothing.

For each step, ask whether it needs judgement or could be code. The model can still help you write that code.

02Why you can't see it

The final answer hides the step that moved.

Here is the social post skill from the lab, drawn as its steps. It reads a blog post and produces three scheduled posts. Four of its six steps could be code. Three things it never says can change the result.

Deterministic, could be code Needs judgement The skill leaves this unsaid

Every run ends in three tidy posts. If one link drops ?lang=en, or the Monday post goes out an hour late, nothing in the final pack tells you. Scoring the whole skill tells you whether it is reliable. It does not tell you where it is not.

04Three sessions

Predict, run, read, fix. Each in a fresh session.

Each session saves its work to a notebook/ folder and the next one picks it up, so you can stop between them. The runs themselves happen in your terminal. Each one is a brand-new Claude Code session in an empty folder that holds only the skill and its input, so the model never sees the answers.

05Checking every step

One file per step, one check per file.

Every step saves a file in a fixed shape, so a check can look in one known place and be exact. The checks are plain code, so the same file gets the same verdict every time. This is part of a real report from one Haiku run of the post generator:

step 4 Fit the limits ● 1/1 Every final post is within its platform's limits ○ 0/1 The character count the step reported is the real count ● 1/1 Shortening kept every link whole Why each check failed step 4 · run 1 · The character count the step reported is the real count linkedin: said 863, actually 861

The post fit. The model still reported a measurement it never made. A two-character error is harmless here and fatal on a post near the limit.

A failed check means one of four things. Open the step's file before you decide which.

The step was wrong

The skill was clear, and the model got it wrong anyway.

The skill left it open

The skill never said, so the model guessed.

Bad input

An earlier step handed this one a wrong file.

The check was wrong

The file is right and the check is mistaken.

Every check in the repo comes with a break() that makes its step wrong on purpose. node bin/lab.mjs selftest proves each check passes on the right answers and fails once broken. While building the lab, it caught one of my own checks that could never fail.

06The fix

Keep the judgement. Hand the counting to code.

Each scenario ships a fixed skill. The steps that needed judgement stay with the model. The rest become short scripts with no dependencies, which the skill runs and the model is told not to second-guess. Step 4 of the post generator shows the most useful pattern, where the model proposes and code decides.

A sentence closes a gap the skill left open. A script closes it the same way on every run and every model, Haiku included.

07Start

Clone it and start with 01.

  • Claude Code, logged in. Each run is one full session on your account and reports what it cost.
  • Node 20 or newer. The repo has no dependencies to install.
  • macOS or Linux. On Windows, use WSL.
git clone https://github.com/dpcleitao/deterministic-code-educational
cd deterministic-code-educational
node bin/lab.mjs selftest

The selftest makes no model calls. Then open Claude Code in the folder and type /lab-map 01.

Five runs shows you where a skill is weak. It is too few to quote a rate. Run ten or twenty before you put a number on anything.
